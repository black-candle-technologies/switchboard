# @lanebucher/switchboard

Version 0.4.2

Switchboard generates Prisma-backed resource configuration and optional
Next.js App Router admin pages.

## Requirements

- Node.js 18 or newer
- A Next.js and Prisma project using TypeScript
- A Prisma schema at `src/prisma/schema.prisma` or `prisma/schema.prisma`

An `@/*` path alias is supported but not required.

## Installation

```bash
npm install --save-dev @lanebucher/switchboard
```

## Quick Start

In an existing Next.js App Router and Prisma project, set `DATABASE_URL` in
`.env`. For SQLite with the default schema location:

```dotenv
DATABASE_URL="file:./dev.db"
SWITCHBOARD_SESSION_SECRET="replace-with-at-least-32-random-characters"
```

Then run:

```bash
npm install --save-dev @lanebucher/switchboard
npx switchboard init
npx switchboard generate --pages
npx switchboard auth seed-admin
npm run dev
```

Open `http://localhost:3000/admin` and sign in with `admin` / `password`.
This default is for local development only and must be changed before
production.

Run the normal Prisma migration and client generation commands before starting
the app. `init` supports both `src/app` and root `app` projects.

## Example App

The repository includes a complete outsider-style example at
[`examples/basic-next-prisma`](../../examples/basic-next-prisma). It contains
`User` and `Post` models, SQLite setup, generated support files, and admin
list/create/edit routes.

From the repository root:

```bash
npm run example:smoke
```

## Init

`init` creates the support files used by generated pages.
This includes `app/admin/switchboard.css`, a small plain-CSS admin theme with
no styling dependency. The generated stylesheet belongs to the project and can
be edited or replaced.

| Option | Description |
| --- | --- |
| `--schema <path>` | Use a custom Prisma schema path. |
| `--app-dir <path>` | Use a custom App Router directory. |
| `--force` | Overwrite existing Switchboard support files whose contents differ. |
| `--dry-run` | Show detected paths and planned file actions without writing files. |

Existing files are skipped by default when their contents differ. Files that
already match the template are reported as unchanged.

```bash
npx switchboard init --dry-run
npx switchboard init
```

`--dry-run` also reports the detected App Router directory, Prisma schema,
source root, and whether generated files will use an `@/*` alias or relative
imports. It also reports the detected auth fields and planned auth files.

Authentication is generated by default. `User` must have one scalar `@id`, a
unique String `username` or `email`, a String `passwordHash` or `password`, and
an enum `role` containing `ADMIN`. `init` fails with migration guidance when
the contract is not met; it never edits the Prisma schema.

Set `SWITCHBOARD_SESSION_SECRET` to a random value of at least 32 characters.
The generated middleware protects every `/admin` route except login/logout.
An existing incompatible `middleware.ts` blocks `init` unless it is integrated
manually or explicitly replaced with `--force`.

## Seed Admin

```bash
npx switchboard auth seed-admin
npx switchboard auth seed-admin --dry-run
npx switchboard auth seed-admin \
  --admin-username admin \
  --admin-password "use-a-strong-password"
```

The command creates the user or resets its password and role. Passwords use a
randomly salted Node `scrypt` hash; plaintext is never stored. The default
`admin` / `password` credentials are insecure and only for local bootstrap.
Run the command again with a strong password before production.

## Generate

| Option | Description |
| --- | --- |
| `-m, --model <modelName>` | Generate only the named Prisma model. |
| `--schema <path>` | Prisma schema path relative to the project root. Defaults to `src/prisma/schema.prisma`. |
| `--out <path>` | Switchboard output directory inside the detected source root. |
| `--app-dir <path>` | Use a custom App Router directory. |
| `--pages` | Also generate Next.js admin routes. |
| `--force` | Overwrite existing resource configs and admin page files. |
| `--dry-run` | Show detected paths and planned file actions without writing files. |

Without `--pages`, the CLI generates resource configs and updates the resource
registry.

Examples:

```bash
npx switchboard generate --model User --pages
npx switchboard generate --pages --dry-run
npx switchboard generate --pages --force
npx switchboard generate --schema prisma/schema.prisma --pages
npx switchboard generate --out src/admin-kit --pages
```

`--out` relocates generated resource configs and the registry. Admin pages
remain under the detected App Router directory.

## Generated Files

`init` creates:

```text
src/
|-- lib/prisma.ts
|-- switchboard/
|   |-- auth.ts
|   |-- auth-actions.ts
|   |-- types.ts
|   |-- registry.ts
|   `-- overrides.ts
|-- middleware.ts
|-- components/
|   |-- form/SmartForm.tsx
|   `-- table/SimpleTable.tsx
`-- app/
    `-- admin/
        |-- switchboard.css
        |-- layout.tsx
        |-- login/page.tsx
        |-- logout/route.ts
        `-- page.tsx
```

Root `app` projects use `lib`, `switchboard`, and `components` at the project
root. `generate --pages` then adds:

```text
switchboard/generated/
|-- UserResource.ts
`-- PostResource.ts

app/admin/
|-- page.tsx
`-- users/
    |-- page.tsx
    |-- new/page.tsx
    `-- [id]/edit/page.tsx
```

For `src/app` projects, these paths are under `src/`.

Resource configs, admin layouts, and list/create/edit pages are created when
missing. Once present, they are owned by the developer: matching files are
reported as unchanged, and differing files are skipped unless `--force` is
provided. The generated registry is the exception; Switchboard updates a
recognizable Switchboard registry so it can add newly generated resources.
An ambiguous custom registry is protected unless `--force` is used.

Both commands report every planned or completed action. `--dry-run` performs
the same detection and planning but creates no files or directories.

## Project Requirements

`init` detects:

- `src/app`, then root `app`
- an explicit `--schema`, then `src/prisma/schema.prisma`, then
  `prisma/schema.prisma`
- `src`-based support directories for `src/app` projects and root-level
  support directories for root `app` projects
- `@/*` mappings from `tsconfig.json` or `jsconfig.json`

When `@/*` maps to `./src/*` in a `src` project or `./*` in a root project,
generated code uses imports such as:

```text
@/lib/prisma
@/components/form/SmartForm
@/components/table/SimpleTable
@/switchboard/types
@/switchboard/overrides
```

If no usable `@/*` mapping exists, Switchboard generates equivalent relative
imports. A config file is not required solely for Switchboard.

Use `--app-dir <path>` or `--schema <path>` when a project stores either item
outside the detected locations. Invalid overrides report the missing path.

Models used with `--pages` must have one explicit `String`, `Int`, or `BigInt`
primary key. Compound IDs are rejected with an actionable error.
